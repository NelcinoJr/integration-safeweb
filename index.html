Detalhamento por Endpoint (Checklist Postman)

Base típica (prefixo): https://pscsafeweb.safewebpss.com.br/Service/Microservice/OAuth/api/v0

QRCode OAuth

1) GET /oauth/authorize

O que faz: inicia a autorização do titular no browser; o PSC redireciona de volta para o redirect_uri com code + state (ou erro).

Pré-condições:
• client_id cadastrado; redirect_uri exato (URL-encoded).
• Gerar PKCE: code_verifier + code_challenge (S256).
• state opaco (anti-CSRF).
O que comprovar:
• Redirect 302 com query completa.
• Sucesso: code + state (igual enviado).
• Negação: error=user_denied + state.

Negativos: redirect_uri errado ou code_challenge ausente.

2) POST /oauth/token (form-urlencoded)

O que faz: troca o code (curta duração) por access_token do titular.

Body: grant_type=authorization_code, client_id, client_secret, code, redirect_uri, code_verifier

Comprovar: HTTP 200 + access_token, token_type=Bearer, expires_in.

Negativos: code expirado/reusado ou verifier errado.

CA (Aplicação Confiável)

3) POST /oauth/authorize-ca (JSON)

O que faz: pede autorização no modelo app confiável; devolve identifierCA via redirect_uri.

Comprovar: Sucesso com identifierCA no retorno. Negação com error=user_denied.

Negativos: login_hint inválido / sem certificado.

4) POST /oauth/pwd_authorize (JSON)

O que faz: obtém access_token usando credencial composta (CA + senha).

password = concatenação identifierCA + senhaDoCertificado

Comprovar: HTTP 200 + access_token, token_type=Bearer, slot_alias.

Negativos: Senha errada (erro claro sem leak) ou identifierCA expirado.

Assinaturas (Bearer = titular)

5) POST /oauth/signature (JSON)

O que faz: assina um ou mais hashes (RAW ou CMS).

Comprovar: raw_signature base64 por ID. Testar single vs multi hash na mesma chamada.

Negativos: Sem Bearer (401), Hash inválido ou OID errado.

6) POST /oauth/signature-icp (JSON)

O que faz: assinatura ICP-Brasil (arquivo ou hash).

Comprovar: Políticas AD-RB e AD-RT. Signature_type 1 (CAdES) e 2 (PAdES).

Negativos: Política incompatível com tipo ou base64 inválido.

7 ao 10) Pipeline PAdES-Signature
  • 7) /start: Envio de PDF; captura de {{document_id}}.
  • 10) /info: Captura de width/height para cálculo de coordenadas.
  • 8) /apply: Aplica annotations (carimbos). Testar com e sem annotations.
  • 9) /finish: Devolve PDF assinado. Validar via abertura manual de PDF.

Negativos: documentId errado ou chamar finish antes do apply.

Consulta / Suporte

11) /certificate-info

Comprovar name, document, email do titular.

12) /certificate-discovery

Recupera PEM/base64 dos certificados ativos.

13) /user-discovery

Consulta situação via client_secret (Status S/N).

Token da Aplicação / Validação

14) POST /oauth/client_token (form-urlencoded)

Emite access_token da aplicação (client_credentials). Negativo: Secret inválido.

15) POST /oauth/signature_verify (JSON)

Valida assinatura ICP. Importante: usa Bearer da aplicação ({{access_token_app}}).

Comprovar: signatureValidation: Valid (1), Invalid (0), Indeterminate (2).

Authorize → Token (User) → Consultas → Signature Hash → Signature ICP → PAdES Pipeline → Client Token → Signature Verify
